### C5. Duplicated derived-state and query patterns in `AppState`

**Finding:** Two repeated patterns inside `AppState`:

**Status:** Documented (candidate).

### C6. `AppState.kt` size diagnosis (981 lines)

**Finding:** Per the audit rule, the large file was diagnosed rather than assumed to need splitting:

- **Concentrates related state:** yes — it is the single Compose state holder for the window; coherent.
- **Contains too much logic:** it is an orchestration layer, not domain logic. All domain/IO work is delegated to Core services.
- **Mixes UI + domain + integration:** it bridges all three but does not implement any of them.
- **Independent responsibilities:** the update/installation block (~110 lines: `checkForUpdates`, `runUpdate`, `autoUpdateIfEnabled`, `refreshInstallationInfo`, `phaseFromLine`, update state) and the quick-fix/lyrics/YouTube block are largely independent of the library/health/organize flows.

**Verdict:** the size is legitimate for a single-window state orchestrator. **No automatic split recommended.** A moderate, justified improvement would extract the update/installation block into its own state class (e.g. `UpdateState`); this is a candidate, not a requirement.

**Status:** Documented (candidate).
